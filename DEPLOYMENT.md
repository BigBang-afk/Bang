# Deploying Aurum

## Backend — Render (Blueprint)

1. Go to https://dashboard.render.com/blueprints → **New Blueprint Instance**.
2. Connect the `BigBang-afk/Bang` repo (branch: `claude/ai-crypto-mexc-platform-r0hbz5`, or `main` once merged).
3. Render reads `render.yaml` at the repo root and provisions:
   - `aurum-postgres` (free Postgres)
   - `aurum-redis` (free Redis)
   - `aurum-backend` (Docker web service built from `backend/Dockerfile`)
4. Before the first deploy, fill in the two secrets Render will prompt for:
   - `API_KEY_ENCRYPTION_KEY` — generate with:
     ```bash
     python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
     ```
   - `CORS_ORIGINS` — a JSON array with your Vercel frontend URL, e.g. `["https://your-app.vercel.app"]`
5. `SECRET_KEY` is auto-generated by Render. `DATABASE_URL` / `REDIS_URL` are wired automatically from the
   provisioned database/cache.
6. Once live, the migration runs automatically on container start (`alembic upgrade head` in the Dockerfile's
   `CMD`), and `/health` should return `{"status":"ok", ...}`.
7. Copy the resulting service URL (e.g. `https://aurum-backend.onrender.com`) — the frontend needs it as
   `NEXT_PUBLIC_API_URL`.

## Frontend — Vercel

1. Import the `BigBang-afk/Bang` repo in Vercel, with **Root Directory** set to `frontend`.
2. Framework preset: Next.js (auto-detected).
3. Add an environment variable:
   - `NEXT_PUBLIC_API_URL` = your Render backend URL from above (no trailing slash).
4. Deploy. Vercel will run `npm install && npm run build` automatically.

Note: `frontend/next.config.js` rewrites `/api/*` to `NEXT_PUBLIC_API_URL` at request time (server-side), so the
browser always calls same-origin `/api/v1/...` and CORS only needs to allow the backend accepting requests
from the Vercel domain (set via the backend's `CORS_ORIGINS`).

## Order of operations

Deploy the backend first (Render) so you have its URL to give to Vercel as `NEXT_PUBLIC_API_URL`. Then deploy
the frontend (Vercel) and go back to Render to set `CORS_ORIGINS` to the resulting Vercel URL, and redeploy
the backend once more so CORS is correct in both directions.
